| S5 | C3's cause | `record_key_validator` fell through to rule 2 ("any other `system/` document -> accepted, unvalidated") for a **catalogued document's own mistyped key**, because it only checked "does this key match", never "is this document catalogued at all". Fixed: a document present in `_ENTRIES_BY_DOCUMENT` now refuses an unmatched key outright (rule 3), matching cardiacFOAM's own posture for its two catalogued documents; only a document this package has NO catalog for at all falls to rule 2 |

Fixed: the native test's sweep/patch/untouched keys now all address keys that already exist in the native dict (`setPurkinjeSlabDict`'s `thickness`/`multiplier`, `setCardiacAnatomyDict`'s `zApicalMid`) |
| S7 | C8's cause | `humanSlab`'s `purkinje_slab` step declared `consumes=(..., "0/Conductivity")` -- the design draft's own worked example did this too, but `0/Conductivity` is `CONDUCTIVITY`'s own `produces`, an intermediate, not an authored input. `enumerate_case_inputs` requires every DAG-wide consumed path to be fingerprintable from the STAGED (not-yet-run) case; an intermediate produced by an earlier step in the same workflow genuinely does not exist yet at plan time, and staging deliberately excludes it from the native-case copy (`record_generated_relpaths`). Fixed by removing it from `consumes` (kept in `produces`, since `setPurkinjeSlab` does rewrite it in place) -- the exact convention cardiacFOAM's own `restitution_curves.py` already documents: "the solve step's mesh comes from the mesh step's produces, so it is not re-declared as consumed" |
